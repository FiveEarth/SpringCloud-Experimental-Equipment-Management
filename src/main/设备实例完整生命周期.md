# 设备实例完整生命周期（实验工具管理平台）

## 一、设备粒度方案概览

| 层级 | 表/概念 | 说明 |
|------|---------|------|
| 设备类型 | `lab_equipment` | 同型号设备（如「电子天平 FA2004」），有 `count` 表示该型号总台数 |
| 设备实例 | `lab_equipment_asset` | 一台实物一条，`asset_code`（如 EQ-P2024001-01）、`status`（0 在库/1 领用中/2 维修中/3 已报废） |
| 领用/归还 | `lab_equipment_apply` | 含 `equipment_id`、`asset_id`，精确到「哪一台」 |
| 维修 | `lab_equipment_maintain` | 含 `equipment_id`、`asset_id`，可选精确到实例 |
| 报废 | `lab_equipment_scrap` | 含 `equipment_id`、`asset_id`，按实例报废 |

可借数量 = 该设备类型下 `lab_equipment_asset.status = 0` 的条数（由设备服务查询）。

## 二、前后端已打通逻辑

### 1. 领用与归还（Apply）

- **开始领用**（学生，我的预约 → 开始领用）  
  - 前端：`POST /api/apply/apply/startBorrow`，body `{ reserveId }`，header `X-User-Id`、`X-User-Name`。  
  - 后端：根据预约查设备类型 → 调用设备服务 `allocateAsset(equipmentId)` 分配一台在库实例 → 写入 `lab_equipment_apply`（含 `asset_id`），标记预约已领用。  
  - 实例：`status` 0 → 1（领用中）。

- **申请归还**（学生，我的领用 → 申请归还）  
  - 前端：`POST /api/apply/apply/return/apply/{id}`。  
  - 后端：该条领用记录 `return_status = 1`（待归还审批）。

- **归还审批**（教师/管理员，归还审批页）  
  - 前端：`GET /api/apply/applies/pendingReturn` 拉列表（含 `asset_code`），`POST /api/apply/apply/return/approve/{id}`，body `{ approved, equipmentStatus, approvalUserName, remarks }`。  
  - 后端：通过则 `return_status = 2`、写 `return_time`，并调用设备服务 `releaseAsset(asset_id)`；若 `equipmentStatus = 1`（故障）再 `setAssetStatus(asset_id, 2)`（维修中）。  
  - 实例：1 → 0（在库）或 1 → 2（维修中）。

- **我的领用 / 归还审批列表**  
  - 接口返回 `asset_code`（LEFT JOIN `lab_equipment_asset`），前端表格展示「实例编号」。

### 2. 设备列表与可借数量（Device）

- **可借设备列表**  
  - 前端：`GET /api/device/devices?borrowable=true`。  
  - 后端：仅查「存在在库实例」的设备类型，`count` = 该类型下 `status = 0` 的实例数。  
  - 前端：表格展示设备名称、编号、型号、实验室、**可借数量**、状态。

### 3. 维修（Maintain）

- **创建维修/报修**  
  - 前端：如我的预约 → 报修，或维修员/管理员提交，body 可带 `equipmentId`、可选 `assetId`。  
  - 后端：写入 `lab_equipment_maintain`（含 `asset_id` 若传）；若 `assetId` 非空，调用设备服务 `setAssetStatus(assetId, 2)`（维修中）。

- **维修员接单**  
  - 后端：`acceptOrder` 更新进度为进行中；若该条记录有 `asset_id`，再 `setAssetStatus(assetId, 2)`，保证实例为维修中。

- **维修员完成**  
  - 成功：若有 `asset_id` 则 `setAssetStatus(assetId, 0)`（在库），否则沿用原设备状态恢复。  
  - 失败（转报废）：创建报废单时带 `scrap.setAssetId(maintain.getAssetId())`，审批通过后该实例置为 3（已报废）。

### 4. 报废（Scrap）

- **审批通过**  
  - 后端：若 `scrap.assetId != null`，调用设备服务 `setAssetStatus(assetId, 3)`；否则沿用原逻辑（设备类型 count-1、status=3）。  
  - 实例：任意 → 3（已报废）。

- **维修无法修复转报废**  
  - 后端：`MaintainServiceImpl.completeRepair(success=false)` 创建报废单时已带 `scrap.setAssetId(maintain.getAssetId())`，与上面审批逻辑衔接。

## 三、完整生命周期（单台实例）

```
                    ┌─────────────────────────────────────────────────────────────┐
                    │                  lab_equipment_asset (实例)                     │
                    │   status: 0 在库 → 1 领用中 → 2 维修中 → 3 已报废              │
                    └─────────────────────────────────────────────────────────────┘

 1. 在库 (0)
      │
      │  学生预约设备类型 → 预约审批通过
      ▼
 2. 学生「开始领用」→ allocateAsset(equipmentId) → 分配该类型下一台在库实例
      │              apply 记录写入 equipment_id + asset_id
      │              实例 0 → 1（领用中）
      ▼
 3. 领用中 (1)
      │
      ├─→ 学生「申请归还」→ return_status=1（待归还审批）
      │        │
      │        │  教师/管理员「通过归还」→ releaseAsset(asset_id)
      │        │  可选：故障 → setAssetStatus(asset_id, 2)
      │        ▼
      │   实例 1 → 0（在库）或 1 → 2（维修中）
      │
      └─→ 报修（可选带 assetId）→ 创建 maintain，setAssetStatus(assetId, 2)
               │
               │  维修员接单/进行中 → 实例保持 2
               │  维修完成 success=true → setAssetStatus(assetId, 0) → 在库
               │  维修完成 success=false → 创建 scrap(assetId) → 审批通过 → 3 已报废
               ▼
           实例 2 → 0 或 2 → 3

 4. 已报废 (3) → 不再参与分配与归还
```

## 四、关键接口与数据流

| 环节 | 前端 | 后端（关键动作） | 实例状态变化 |
|------|------|------------------|--------------|
| 可借列表 | GET /api/device/devices?borrowable=true | 按在库实例数算 count | - |
| 开始领用 | POST /api/apply/apply/startBorrow | allocateAsset → 写 apply.asset_id | 0→1 |
| 申请归还 | POST /api/apply/apply/return/apply/{id} | return_status=1 | - |
| 归还审批通过 | POST /api/apply/apply/return/approve/{id} | releaseAsset(asset_id)；可选 setAssetStatus(asset_id,2) | 1→0 或 1→2 |
| 创建维修 | POST /api/maintain/maintain（可带 assetId） | 写 maintain.asset_id；可选 setAssetStatus(assetId,2) | 0/1→2 |
| 维修接单 | POST /api/maintain/maintain/{id}/accept | setAssetStatus(assetId,2)（若有 asset_id） | - |
| 维修完成成功 | POST /api/maintain/maintain/{id}/complete success=true | setAssetStatus(assetId,0) | 2→0 |
| 维修完成转报废 | POST /api/maintain/maintain/{id}/complete success=false | 创建 scrap(assetId)；审批后 setAssetStatus(assetId,3) | 2→3 |
| 报废审批通过 | POST /api/scrap/scraps/{id}/approve status=1 | 若 assetId 非空则 setAssetStatus(assetId,3) | →3 |

## 五、前端页面与实例展示

- **可借用设备**：可借数量 = 实例在库数，无需改页面逻辑。  
- **我的预约**：开始领用 → 调用 startBorrow，后台自动分配实例。  
- **我的领用**：列表展示「实例编号」（asset_code），操作「申请归还」。  
- **归还审批**：列表展示「实例编号」，操作「通过归还/驳回归还」。  
- **维修**：创建时可选传 `assetId`（后续可做「选择实例」下拉）；维修完成转报废时后端自动带 assetId。  
- **报废审批**：列表展示设备名称等；通过时后端按 scrap.assetId 更新实例状态。

以上为当前前后端已实现的设备实例粒度与完整生命周期说明。
